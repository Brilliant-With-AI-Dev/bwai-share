Mirror experience configuration

A plain-English YAML walkthrough

1 / 7

One file sets the experience

The YAML holds values. Existing code still runs the product.

The YAML

schemaVersion: 1
app: …
copy: …
timing: …
flow: …

What it means

  • One readable source per app
  • Validated before the website builds
  • Compiled into ordinary TypeScript

Safety boundary: The live app never reads YAML directly.

App identifies the product

These values name Mirror inside code and on screen.

The YAML

app:
  id: "mirror-next"
  routePrefix: "/mirror"
  displayName: "AI Mirror Experience"

What it means

  • id keeps the existing internal identity
  • routePrefix keeps every URL under /mirror
  • displayName supplies the full product name

Safety boundary: Changing a value cannot create a new route.

Copy holds customer-facing words

Product language becomes easy to find and review.

The YAML

copy:
  productLabel: "AI Mirror Experience"
  productNameShort: "AI Mirror"
  loginTitle: "AI Mirror\nExperience"
  loginQuote: "Most teams are running on 20%…"
  supportEmail: "nish@brilliantwith.ai"

What it means

  • Login messaging lives together
  • Emails and downloads use the same source
  • Every text field has a size limit

Safety boundary: Copy changes cannot execute code.

Step titles label existing pages

The browser titles move into YAML, not the journey.

The YAML

stepTitles:
  start: "Start | AI Mirror Experience"
  form: "About You | AI Mirror Experience"
  interview: "Interview | AI Mirror Experience"
  mirror-letter: "Your Mirror Letter | AI Mirror Experience"
  action-plan: "Your Action Plan | AI Mirror Experience"

What it means

  • Keys point to code-owned steps
  • Values control each browser title
  • All current titles remain identical

Safety boundary: Step order and transitions remain in code.

Timing holds safe operational knobs

The same file controls bounded waits and retries.

The YAML

timing:
  preparationPollIntervalMs: 500
  preparationTimeoutSeconds: 120
  mockPreparationMs: 2000
  stageRequestTimeoutMs: 270000
  maxStageDispatchAttempts: 2

What it means

  • Polling checks every half-second
  • Preparation stops after two minutes
  • A refused stage receives one retry

Safety boundary: Validation rejects unsafe numbers and relationships.

Flow states who controls movement

Version one deliberately keeps the journey in code.

The YAML

flow:
  source: "code"

What it means

  • Only the exact value code is accepted
  • YAML cannot contain expressions
  • Future workflows need a reviewed schema version

Safety boundary: No second workflow engine is created.

YAML becomes safe runtime data

A build-time trust gate separates authors from runtime.

The build pipeline

mirror.experience.yaml
        ↓ validate everything
ExperienceConfigSchema
        ↓ generate once
mirror.experience.generated.ts
        ↓ import values
Existing Mirror code

What it means

  • Invalid YAML reports every problem
  • Stale generated output fails testing
  • Mirror behavior remains unchanged

Safety boundary: Routes, components, prompts, and models stay code-owned.
