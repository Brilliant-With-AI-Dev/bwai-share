The Matt Pocock flow, automated

You already know the pattern. SSSF writes that pattern down so Python can run it the same way each time.

/ask-matt explains which skill comes next. You or the agent starts each skill. Documents and issues carry the work between steps. That works well because each skill has one job.

The main difference: an SSSF Python script starts each next step automatically. It also decides when to retry, stop, or accept the whole run.

Closest matches

/ask-matt flow → the whole ADW

An ADW is simply the saved sequence: who works next, what check runs, and when the work stops.

/grill-with-docs → useful before SSSF

Grilling sharpens the request with you. The starter SSSF planner does not interview; it plans from the request it receives.

/to-prd and /to-issues → planner

Both turn a shaped request into work another agent can pick up.

/implement → builder

Both read the plan and change the product.

/tdd → builder plus test loop

The builder fixes code. A fixed command runs tests. Failures return to the builder.

/review-branch → reviewer

Both compare the result with what was requested before calling it done.

/handoff → shared file plus short summary

Both preserve what the next role needs. SSSF does this automatically between steps.

Useful together Use Matt’s grilling skills to shape important work with human judgment. Use SSSF when the execution pattern is settled and worth repeating.

Four SSSF words, translated

  • ADW: the saved skill sequence.
  • Roster: the list of available roles.
  • Envelope: the short handoff summary.
  • Gate: an automatic yes-or-no check.

That is enough vocabulary for now. The exact file formats can wait until you customize one.
