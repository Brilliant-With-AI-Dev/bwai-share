How handoffs earn trust

An agent’s answer is not trusted because it sounds confident. SSSF requires a typed report, checks its claims, and corrects failures in the same session.

Your win By the end, you can explain what an envelope does, what a gate does, and what happens when either fails.

Two outputs, exactly

An SSSF agent can leave two kinds of output:

Reference files

The work product

Plans, findings, or notes written into the shared context_handoff/ directory.

JSON envelope

The claim report

A typed summary naming status, artifacts, and facts the next phase needs.

Nothing else

No conversational handoff

Python moves files and structured data forward. Agents do not rely on hidden chat between roles.

The parser answers: “Does this report match the required structure?” A gate answers: “Are its checkable claims true?”

Example: a planner returns a valid PlanOutput envelope claiming it wrote context_handoff/plan.md. The parser can confirm the JSON fields. The artifacts_exist gate checks whether that file actually exists. A separate files_non_empty gate checks whether it contains anything.

Gates verify evidence, not quality A gate can prove a plan file exists and is non-empty. It cannot prove the plan is wise. Quality judgment still belongs to a reviewer agent or engineer.

Why corrections keep the same session

If JSON is malformed or a gate fails, SSSF names the defect and sends it back to the same agent session. The agent keeps the context that produced the near-miss. A cold restart would discard that context and pay again to rebuild it.

Retries stay bounded. JSON repair has its own attempt limit. Gate corrections use the phase’s configured retries. Exhausting either limit fails the phase instead of looping forever.

The customization trap

Every typed output contract appears in three connected places:

  1. The Python output type
  2. The JSON example in the agent’s user prompt
  3. The output_type= named at the call site

Change one and you must update all three. If they drift, every run spends correction attempts reconciling contradictory instructions.

Retrieval practice

1. An envelope claims plan.md exists, but the file is missing. What catches this?

2. The agent returns malformed JSON. What happens first?

Check your understanding

  • I can distinguish a work-product file from its envelope.
  • I can distinguish typed parsing from claim verification.
  • I know why failed checks correct the same session.
