SSSF handoff loop

How agent work becomes structured, checked input for the next phase.

Two outputs

File

Work product

Written into the session’s shared context_handoff/.

Envelope

Claim report

Typed JSON with status, summary, artifacts, and role-specific fields.

Python

Transfer

Persists both and injects the previous envelope into the next prompt.

Verification path

agent output
→
typed parse
→
gates
→
next phase
If parsing or gates failSend the named defect to the same agent session. Retry only within configured bounds. Then fail the phase.

Different questions

  • Parser: Does JSON match the required type?
  • Gate: Are mechanically checkable claims true?
  • Reviewer: Is the work actually good?
  • run.finish(): Did phases pass and acceptance hold?

Synced contract

Python output type
        ↕
user.md JSON example
        ↕

Change all three together. Drift causes repeat correction costs.
